## 3. 合并预演与冲突规则

已执行不改变分支或工作区的 `git merge-tree --write-tree --name-only origin/release/v0.2.8 v0.2.14`。返回 1 表示有冲突，不是可发布候选。预演树为 `24606c79afcb65050d1748d651f67c928a2c2902`，包含冲突标记，禁止构建或发布。

四个冲突文件及处置：

1. `backend/internal/server/router.go`：采用上游支付路由新增的 Redis 参数，同时保留本地 Studio verifier 初始化和独立认证路由注册。不能整块选择 theirs，避免 Studio 再次 404。
2. `backend/internal/repository/email_cache.go`：采用上游哈希 token、Lua 原子 compare-and-delete 和验证码原子计数；替换旧明文/WATCH 实现，不能保留两份同名函数。
3. `backend/internal/service/email_service.go`：接口、存储、校验和消费统一使用上游新语义，保留 Router/Studio 共享调用入口；同步更新本地 stub/mock，验证两产品的重置与并发单次消费。
4. `backend/ent/migrate/schema.go`：保留本地 PaymentOrder 到 PaymentPlan 的关系，加入上游 bonus_amount。用既有 Ent 命令重新生成，不手工猜外键列下标；检查付款计划、退款等本地字段没有丢失。

预演没有文件删除；58 个以 Studio auth / image creation 命名的本地文件保持不变。但共享路由、邮箱服务、ORM 和计费改动仍能影响这些功能，不能以“文件未变”替代回归验证。

## 6. 用户可见变更与发布注意事项

- API Key 限制默认 200 个有效 Key/用户、60 次创建/小时；现有 Key 不会因此失效。上线前核对运营需求，按上游默认实现，配置调整单独确认，不擅自关闭。
- 余额在途预占默认开启，主要改变低余额并发准入；实际扣款仍按真实 usage。覆盖订阅绕过、免费分组、别名定价、长请求续期、错误/取消释放、异步结算和 Key 已删除场景。
- 重置密码 token 改为哈希，升级前未使用链接会失效；Router 和 Studio 均提示重新申请，不做明文兼容回退。
- 充值促销功能合入，但不主动修改生产赠金/折扣配置，不启用新支付渠道。首次发布验收期间保持促销未启用；启用赠金需另行确认，并先通过下述兼容回退关卡，不为此修改本次 upstream 业务实现。
- EasyPay 安全补丁完整保留：回调字段白名单、return_url 查询清理、合法通知/订单对账回归。特殊支付提供商是否兼容必须测试，不能因共享上游风险而忽略该修复。
- 首次安装管理员规则变更不应阻断已存在用户的生产启动；验证现有安装和全新安装两种状态。
- `v0.2.14` tag 的 backend/cmd/server/VERSION 仍写 0.2.13。候选构建显式固定 VERSION=0.2.14 和最终 COMMIT，核对二进制 --version / 镜像元数据，不凭 tag 标签宣称版本一致。
- 本次更新不承诺解决 9 月 30 日观察到的账号上游 429/503 与上传等待。上线后对同类流量重新测量 TTFT、总耗时、重试和预占拒绝，不混入未验证的性能调参。

## 7. 执行顺序

1. 重查远端、release 起点、新本地开发与 worktree 状态；固定目标 tag，避免执行期间目标漂移。
2. 新建隔离 `release/v0.2.14` worktree，起点固定 b13ef536a；直接 merge v0.2.14，不切换主工作区。
3. 按上述四项处理冲突、新迁移编号和生成代码；对自动合并的 shared auth / gateway / billing 路径逐项检查。
4. 跑本地验证；审查 v0.2.8 到候选的新增差异，同时审查 origin/main 到候选的整体累计差异。逐项检查本地保护清单，不能只看文本冲突。
5. 真实阻断问题修复后重跑验证；无阻断时提交并推送 release 到 origin，交付审查结果和网页验收单。
6. 停止等待部署授权。当前没有测试环境，不能启动旧 sub2api-test 或把“执行合并”当成部署许可。
7. 另获生产授权后，本机构建 linux/amd64 Docker 镜像并上传 Router 生产环境，固定相同镜像/commit，只替换 Router，验证后再合并 main。

重点必须有证据：

- EmailCache 原子验证码次数、hash reset token 单次消费与所有本地 mock 编译；Studio 签名/角色/2FA/密码恢复、图像 session/API 资格。
- EasyPay 伪造通知拒绝/正常回调接受、return_url、微信退款、充值折扣/赠金/affiliate，测试中不发生真实扣款。
- 赠金回退兼容：用测试订单验证实充 100、赠金 10 时返利基数为 100 而非 110；覆盖待支付订单升级后回调、已支付未完成订单重试和重复通知幂等。在相同已升级数据库上检查拟用回退镜像，原始 v0.2.8 按 Amount=110 计算的行为视为不兼容，不以“能启动/能读新增列”判定通过。
- 余额预占并发/续期/释放/结算、余额及订阅模式、删除 Key 后仍计费、价格与 effort multiplier 口径。
- HTTP Responses、Chat Completions、Messages、WS rollover/取消、复合分组模型归属、usage 转换、首字与错误快照。
- 新迁移升级/校验和/约束、新 schema 生成一致性，以及既有本地 PaymentPlan 关系。
- UseKeyModal：兼容/API Key 两种模式 x 远程/本地目录 x HTTP/WS；对应 provider 的 base_url、密钥来源及 discovery 配置。
- 账号重置只用 mock/测试数据，不消费真实 Claude/OpenAI 重置额度；新 TypeSafe 平台不凭文本配置声称上游请求成功。

## 9. 生产验收与回退边界

部署待单独授权，遵守 docs/engineering/deployment.md 和 sub2api-ops，并先核对未提交 DNS 运维工作的当前有效状态。

- 备份两生产数据库与当前配置，确认可读回；冻结当前镜像、挂载、网络、签名配置和回退容器，保留 Studio 及其他服务。
- 本次只替换唯一 fx-production-router；router/fx 是同一服务入口，不执行历史双生产流程。Studio 应用不随 Router 升级。
- 真实验收：Router health、两域名路径、未签名 Studio auth 401 而非 404、可信签名认证和角色/密码恢复、插件页面/API、合适模型的流式请求、DNS/上游可达。
- 支付配置读取/测试订单与真实收付款分开记录；真实交易另需授权。观察低余额并发拒绝、预占残留、TTFT/耗时/429/503/499、CPU/内存及迁移锁等待。
- 回退只恢复兼容应用镜像及当前配置，不恢复旧数据库覆盖新写入。263/264 保留并验证旧应用对新增列和平台记录的兼容性；新 TypeSafe 账号/路由创建前明确回退限制。
- 赠金启用关卡：记录促销配置状态并准备已验证返利基数及幂等的兼容回退镜像。未通过前不启用赠金；生产配置变更另获授权。默认关闭不等于启用后仍可安全回退。
- 回退决策：先核对数据库中 bonus_amount > 0 的订单及其支付/履约/返利状态。一旦已有赠金订单，禁止直接恢复原始 v0.2.8 镜像，包括“先关闭促销再回退”；关闭促销不能改变已产生订单。使用已通过上述测试的兼容镜像，或保留当前版本前向修复，具体操作另行授权，不手工改历史订单/余额/返利，也不清空订单来绕过限制。
- 密码 reset token 新旧格式不兼容，回退也要求重新申请链接；不要以恢复明文 token 规避安全修复。

停止条件：基线不一致、冲突/生成代码不完整、历史迁移改变、Studio 路由丢失、支付安全回归、预占泄漏/错扣、失败测试无法解释、当前备份或生产真实业务验收失败。赠金回退兼容未验证时停止赠金启用；已有赠金订单时停止向原始 v0.2.8 回退，不阻碍保持赠金关闭的代码合并。
