## L1.2 同类路径对照

参考路径：上述预算 helper、现有 Studio 路由与新增 MCP 路由。执行时逐分支对照：

- 普通 JSON、gzip/deflate/zstd、unknown Content-Length、BOM/控制字符规范化：采用预算版本；保留 64 MiB 解压边界，拒绝而非截断。
- 已 preread 借用 body：不重复收费，不把仍被上游引用的内存提前当作释放。
- 同步 SSE：最终 body 在 handler 返回前持有；上游思考不被误当作整条响应 120 秒超时。
- failover：每轮转换临时预算及时归还；不能累计到后续正常重试误报 503，也不能绕过预算换 unbudgeted map 实现。
- 异步生图：202 前接管 reservation；handler 返回后任务仍持有；创建失败/取消/任务完成分别且只释放一次。
- Studio 与 MCP：内部 HMAC 和公网 OAuth 独立，MCP 开关关闭不影响 Studio；discovery 不被 SPA 伪装成成功。

## L2.2 状态机

```text
Ingress -> 共享预算 + 单请求limit -> 分块读入/解压/规范化
  大小超限 -> 413；容量不足 -> 503/Retry-After；读停滞 -> 408；客户端走开 -> abort/499
  同步 -> 等待账号/用户slot -> attempt临时scope -> 上游请求 -> SSE/JSON
    可重试 -> 释放本轮patch临时scope -> 按同账号/换号上限重试，不重用已写响应/重复计费
    客户端走开 -> 有限drain收usage -> 只提交一次结算 -> handler释放最终body
  异步 -> 202前detach/takeover预算 -> Redis任务owner绑定 -> worker继续 -> 完成/失败/取消释放
    拒绝创建 -> release；poll仅对原user/key，不因功能关闭遗弃已接受任务

MCP默认关闭；显式启用后：固定resource -> PKCE授权码 -> JWT浏览器明确同意
  -> grant + 摘要token -> user/admin + read_only + 路由目录/范围再检查 -> 审计
  -> refresh旋转；code/refresh重放 -> 撤销family；拒绝凭证形式歧义/权限降级绕过
```

并发点：共享预算release/async接管、同一gin.Context复用、SSE队列关闭、快照共享对象写入、旧模型目录回写覆盖、幂等键跨策略复用。执行必须覆盖race/取消/重试，而非只有成功请求。

## L2-ops 可观测性与兼容

| 失败模式 | 区分证据 | 验证/处理 |
| --- | --- | --- |

## L2-perf 容量实验

| 维度 | 上界/风险 | 证据要求 |
| --- | --- | --- |
| fan-out | Gemini同账号默认4次重试（额外次数），范围0-10；还存在换号上限，二者不是总共4次 | 真实执行次数/最长时长测试；每轮patch预算释放、无重复结算 |
| body内存 | 预算是实例级入口分配记账，不等于RSS硬上限；长SSE保留body，图片/转换/cache/GC另有占用 | 1.5GiB容器级本地实验；59/85MiB并发与压缩/重试取消，记录峰值RSS、残留heap和503率 |
| SSE/会话 | queue8MiB不是frame8MiB；单行500MiB仍可能占大内存；三类会话cache各16384项/32MiB | 大帧兼容、队列满/取消释放、LRU淘汰/续接失效行为；不凭分配benchmark宣称稳定 |
| 延迟 | 热路径moego/少解析可能降CPU；usage overflow=sync与配额持久化可能增加handler尾耗时 | 同数据集p50/p95/p99/TTFT及DB调用次数比较，区分上游思考、队列、写阻塞和本地CPU |
| 并发/后台 | usage worker数量不等于DB全局并发；通知可丢弃但收费提交不能按同策略丢弃 | 队列满/DB慢/任务取消/shutdown/race，记录goroutine与连接等待，使用合成账务数据 |

本轮不设 GOMEMLIMIT、不扩大线上容器、不关闭预算来追求零503。既有snapshot1基准继续跑，同时增加真实HTTP生命周期验证。
