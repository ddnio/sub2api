## 必须先处理的兼容性

1. **GPT-5.5 订阅退役**：上游按实际账号类型和映射后的 upstream model 判断，OAuth/SetupToken/shadow 指向 gpt-5.5 时不再调度/展示；API Key 上游仍允许，客户端使用本中转站 Key 不代表上游账号就是 API Key。旧对话、白名单、远程模型目录、compact 和别名映射都须覆盖。发布前只读盘点生产默认模型、映射与近期用量；受影响时先给用户清单和替代方案，未确认迁移方案停止发布。不擅自把 gpt-5.5 改名映射到其他模型，不为了保留旧用法撤销上游退役校验。
2. **平台清单与协议路由**：覆盖 OpenAI OAuth/API Key、Anthropic OAuth、国产多协议、composite 与未知模型；OAuth 凭据绝不可因归属歧义进入错误管线。新增平台代码合入，不主动创建账号、启用渠道或修改现有用户分组。
3. **支付与退款**：上游修改确认回调、订单类型和退款 pending 余额/订阅扣减时序。本地微信、PaymentPlan、折扣/赠金、affiliate 幂等必须整体回归；不得仅凭文本自动合并判定兼容。旧 pending 订单跨版本处理必须验证。
4. **Gemini 显式缓存**：涉及真实上游资源、账号绑定、租约、Key/订阅金额预留、渠道计费，不是普通 Redis 缓存。必须验证租户隔离、并发改 TTL、失败恢复/补偿、取消和去重。不主动创建生产收费缓存；是否允许真实调用由部署验收授权范围决定。
5. **内存/重试**：保留 snapshot1 的入口先限长再 JSON 解析。v0.2.15 的 namespace 按需重建不能证明 OAuth 全量解码和大请求重试的内存风险已经消失。用本地大 body + 多轮错误模拟测峰值/分配、取消后释放和并发恢复，不做真实生产压测，也不趁合并擅自调 Docker/GOMEMLIMIT。
6. **Studio/生图**：保留签名认证、nonce 防重放、public ID/角色、2FA、密码恢复、插件资格/会话与自定义页面隔离；保护共享转换中的 image/tool_result、Responses 与 OAuth 生图链路。Studio 是独立发布，本次不替换其应用。

| Gemini 缓存与 pending 退款可安全回退 | 本地模拟上游与 PG/Redis 故障、并发、恢复；候选/旧镜像对同一升级后测试库比较 | 准备兼容回退或明确阻止发布 |
| 服务器当前容量可承受候选 | 部署授权后只读核对 RSS/swap/PSI/磁盘/队列，再做小规模真实验收 | 不靠默认加内存强行上线，先解决容量缺口 |

本轮没有新的运行期实验数据；不能把历史 30 分钟 snapshot 观察当新候选容量验证。规划静态证据可完成，但上线运行期 gate 尚未完成。

## L2.2 状态机与并发

```text
入站鉴权 -> group/模型映射 -> 账号类型/退役/协议归属过滤 -> 账号 slot + 余额预占
  成功 -> 流式/非流式 usage -> 幂等结算 -> 释放 slot/预占
  可重试且未跨越安全重放边界 -> 错误策略(整号/模型级) -> 同号退避或换号
  客户端取消/不可重试 -> 记录有界错误快照 -> 释放 slot/预占
  WS 后续轮次 -> 刷新分组价格，不复用上轮结算或旧路由状态

显式缓存创建 -> Key/订阅固定金额预留 -> 指定账号上游创建 -> 绑定/费用提交
TTL 修改 -> 唯一 mutation lease -> 上游修改 -> 原子提交/失败补偿
取消、超时、进程退出 -> 对照实际上游资源恢复，不能把未知视为未发送

退款申请 -> 预扣 -> 网关 pending -> 定时/手动查询
  成功 -> 终态与账务只提交一次
  确认失败 -> 原子恢复预扣一次
  未知/查询异常 -> 保持 pending，不提前退回或再次预扣
```

用 PG/Redis 并发用例验证租约、幂等与故障恢复，不能只以顺序 mock 测试代替。

## L2-ops：观测与兼容发布

## L2-perf：性能边界

| 路径 | 对比与上界策略 | 验证 |
| --- | --- | --- |
| body/JSON | 保留 snapshot1 1 MiB 处理上限、256 KiB 存储上限；OAuth 转换本身仍可能全量解码 | 1 MiB 边界、59 MiB、多轮错误、并发小请求隔离；不承诺上游已根治内存 |
